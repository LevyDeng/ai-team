# AI 小队工作台使用说明

从源码目录双击 `ai-team.cmd` 打开工作台。首次启动和远端配置见[安装与连接指南](SETUP.md)。

固定到任务栏后若出现 Electron 默认页，请取消旧的固定图标，从正确快捷方式打开后重新固定。项目目录里的 `AI 小队.lnk` 打开新版，`AI 小队（经典版）.lnk` 打开旧版。也可运行 `Create-DesktopShortcut.ps1 -Both` 在桌面生成两份快捷方式。两版均保留自己的任务栏标识和完整启动入口；此操作不改变聊天记录或连接设置。

## 三个概念

- **角色**：名字、头像、角色设定、发言风格示例，以及 Agent、Provider 和运行位置。这里的模型与推理强度是新对话的默认值；每个对话可独立修改。
- **项目**：邀请哪些角色、配置哪些工作目录。同一项目的所有对话共用一批终端和文件浏览器。
- **位置**：一台机器。连接方式负责连通，操控方式负责执行命令或操作桌面。内置本机不可删除；远端首版支持 SSH。

## 开始使用

1. 在“角色”中设置角色。角色设定和发言风格都是自由文本，可以留空。
2. 展开“连接配置”，选择 Agent、Provider 和运行位置。
3. 在项目名称旁的菜单中配置目录、邀请角色。本地目录可点“浏览…”选择文件夹，也可手动输入；远程目录仍手动输入。每个角色的运行位置都需要有对应项目目录。第一个目录是文件和终端的默认目录。
4. 在对话列表上方点加号，用角色选择器搜索并选择参与者：选一个角色是单聊，选多个是群聊。这里显示所有已创建的角色，未加入项目的角色会在保存时一并加入；已选角色可单独移除或清空。
5. 发送消息。在输入框里输入 `@`，选择本对话的发言角色；继续输入名字可筛选。支持连续指定多个角色，或选择“所有角色”。没有指定时，群聊由所有参与角色依次发言。可设置讨论轮数上限、暂停或让一个角色总结。

接力群聊的轮数是上限，可在 1–50 之间输入，按对话保存；默认 1 轮，避免自动增加消耗。默认开启“AI 判断提前结束”：每轮所有参与者发言后，只有全部认为讨论完成才提前结束；需要你补充信息时会暂停。结束判定缺失或格式错误时，也会停止自动追加，并明确显示“结束判定不完整”，不会冒充讨论完成。达到上限只表示停止追加，不表示问题已经解决；你仍可继续发消息。

未指定主持人时，结束判断随角色正常回复返回，不额外调用裁判模型，但会增加少量控制文字。指定主持人后，由主持人每轮单独判断一次。AI 判断可能出错。取消勾选后会执行指定轮数，不再额外调用主持人判断，仍可手动暂停；调用失败或中断会停止后续发言。单聊、独立作答和单次总结仅执行一次。轮数无法精确限制 Token，总消耗还取决于参与人数、上下文长度、工具调用和每次回复的长度。

`@` 菜单支持方向键选择、Enter / Tab 确认、Esc 关闭；菜单展开时 Enter 用于选人，关闭后 Enter 才发送，Shift+Enter 换行。只选人而没有消息正文时不会启动任务。角色名保留在消息与草稿里，切换聊天或重开后仍可识别；邮箱地址和代码中的 `@` 不用于分配角色。上方不再常驻显示发言角色选择框。

打开 App、选择项目或选择聊天不会连接 SSH。发送任务、测试连接、打开远端文件/终端或获取远端模型列表属于明确的连接操作。

## 输入队列与插队

- 空闲时，Enter 或“发送”正常启动任务；运行时，Enter 或“加入队列”保存下一条消息。Shift+Enter 仍然换行。每个对话有独立队列，最多待发送 20 条，不会额外启动一批 Agent。
- 队列显示在输入框上方，可收起，也可调整顺序、编辑、移除或暂停。编辑会移回空输入框；如果已有草稿，会保留两边内容并提示先处理草稿。
- “立即插队”或队列中的“插队”会中断当前轮，等确认停止后优先发送该消息。已输出内容保留，被打断的任务不会自动重做，也不会回滚已经执行的操作。随后继续原来的待发送队列。
- 单聊等待本次任务结束；群聊等待整个提交任务的全部参与者及轮次结束。每条消息保留自己的附件、发言角色顺序、模型与推理强度。尚未发送的消息不会提前进入模型上下文；附件仍然只发送路径，不提前上传原文件。
- 调用失败、需要用户决定、讨论结束状态未确认，或无法确认远程任务已停止时，后续消息保留并暂停。处理后点“继续队列”。交互终端还需回到可输入状态；结束交互终端会暂停队列。
- 队列会保存到本机。重开 App 后默认暂停，需手动继续，避免后台悄悄补发。已进入发送历史的任务不会因重开而再提交一次。

输入框旁的「结束任务」会请求当前任务停止。若任务卡住，可点击对话顶部的红色「强制结束」并确认。本机后台任务会直接回收对应进程树，远程任务会由执行器强制结束对应进程组。已收到的回复和待发消息会保留，本机后台任务的强制结束请求在重开后仍有效。

「立即插队」将消息移到队首，确认当前任务停止后再发送。如果未能确认停止，队列会暂停，待发消息会保留。

本机 Codex CLI 0.170 及以上版本可在交互终端运行时使用「插话」。先在任务输出中建立 Codex 交互连接，在聊天输入框选中正在运行的角色并输入文字，再点击「插话」。消息会进入同一轮 Codex 对话。通过普通聊天后台启动的任务继续使用队列和插队。

## Android 手机连接

在项目根目录运行 `py -3.12 -m pip install --target .runtime/workbench/phone/deps cryptography qrcode`，安装电脑端的配对依赖。运行 `android/build.ps1` 可构建手机端 APK。手机与电脑连接同一个 Wi-Fi 后，在桌面端打开「对话设置 → 手机连接」，用 Android 客户端扫码或粘贴配对码，即可收发当前对话的文字消息。

## 工作流

在项目侧栏点「工作流 → 新建」。填写任务目标和验收标准，可以创建带执行、验收和返工上限的工作流。各阶段可按候选顺序运行，也可请主持人从该阶段的候选角色中选人。

点「AI 生成工作流」可根据目标生成 1 到 12 个顺序步骤。先检查预览中的任务与完成条件，再确认排队。每个步骤可以单独设置选人方式：

- **自动选人**：到该步骤开始时，才读取项目中角色的最新评分。可指定主持人结合上下文选择。主持人不可用时按评分选人；没有匹配评分也无法取得主持人结果时，工作流会暂停，等待你补评分、指定角色或调整主持人。
- **指定名单**：按该步骤的名单顺序运行；已确认候选不可用时才尝试备选。选一位时由指定角色负责。

在「角色 → 工作流评分」可按「领域 × 职责」填写 1 到 10 分。领域和职责可自定义，未填写的组合表示未评分。例如同一角色的「前端 × 审核」可以是 9 分，「前端 × 实施」可以是 4 分。生成预览允许修正步骤的领域和职责，评分修改会影响尚未开始选人的步骤。

工作流的运行记录可查看每步选择的角色和依据。完成后可点「再次运行」，复用方案并按当时的评分为自动步骤重新选人。暂停或结果不确定时，先查看任务输出和工作目录，再按需重试当前步骤。

## 重启、退出与支持

左下角「工作台」菜单可切换保持唤醒、重启或退出。在「设置 → 关于」可查看项目简介、版本并扫码打赏，页面右上角和简介卡片底部均提供 GitHub 仓库入口。

- **重启工作台**：由后台执行器管理的本机任务可以继续运行。工作台自身仍在管理任务或终端时，界面会提示等待。
- **退出工作台**：有活动任务时先确认。确认后尝试结束任务和终端，已保存的对话和待发送消息会保留。

## 对话模型与群聊顺序

点击聊天顶部或消息旁的角色头像，可修改该角色在本对话使用的模型、推理强度，也可读取和刷新模型列表。保存后，下次发送直接生效，无需重连；已开始的整轮任务保留发送时的设置。输入框的快捷模型设置也只作用于本对话。已明确保存的对话选择不会随角色默认值改变；对话中的模型或强度留空，则分别跟随角色默认值。

界面和任务启动共用同一套解析规则：对话明确选择优先，其次是角色默认。例如角色是 `gpt-6.1-sol / high`，旧对话两项为空时，发送仍明确指定 `gpt-6.1-sol / high`。复用桌面版登录不会让空值转而采用桌面版的默认模型；若对话与角色都没设置模型，会提示先选择，并保留提问。任务输出开头会记录本次请求的模型和强度。

群聊输入框上方可选择：

- **接力讨论**：后一个角色可以读取前面角色的回复。默认采用此方式。
- **独立作答**：各角色读取用户消息与自己的历史回复，不传入其他角色的回复。点击“总结讨论”则会显式把所有角色的内容交给总结者。

发送前显示实际发言顺序。在聊天右上角“对话设置”中，可按“上移／下移”调整参与者顺序并保存；新建群聊时也可直接设置。输入框上方的“调整默认顺序”仍可快速调整。顺序按对话保存，不会改变另一个群聊。运行中的讨论需先暂停才能更改参与者和顺序。

未写 `@` 或选择 `@所有角色` 时，按保存的顺序依次执行；显式 `@` 按首次出现的顺序，同一角色重复提及不会重新排队。例如 `@claude … @gpt … @gpt … @claude` 仍按 Claude、GPT 执行。`@所有角色 @总结者` 可让所有角色发言，并把首次单独指定的“总结者”移到最后，不会让它重复发言；后续再次提及不改变顺序。多轮沿用同一顺序。

## 群聊主持人

打开聊天右上角“对话设置”，在发言顺序下方的“群聊主持人”中选择一位本对话成员。使用该角色在本对话中的模型、推理强度、账号和运行位置。默认“不指定”，旧群聊保持原有行为。成员选择和顺序也统一在这里修改；顶部不再另设“邀请角色”按钮。设置弹框右上角均有关闭按钮，直接关闭不保存未提交的表单修改。

- **判断是否结束**：开启输入框上方的“AI 判断提前结束”后，在还有后续轮次时，主持人单独判断“继续”“完成”或“需要你补充信息／决定”。上限只有 1 轮或已经到最后一轮时，不额外调用主持人作结束判断，也不要求参与者投结束票。主持人不能提高轮数上限，也不会替你作出授权。关闭此选项后不调用主持人作结束判断。
- **压缩长历史**：可勾选“长历史自动压缩，保留原始记录”。有效历史达到约 48 KiB 且有足够早期消息时，主持人生成早期消息摘要；最新用户提问和最近八条消息继续完整传入。摘要保存到本地，重开 App 后继续使用。摘要绑定所覆盖原文，原文变化时自动回退；更换主持人会清除旧摘要。关闭压缩后恢复使用原文。
- **查看原文与过程**：原始聊天记录不删除。主持人输入过长时通过只读历史工具分段读取，程序检查完整读取后才采用结果；普通角色使用摘要时也能按需读取原文。聊天中的主持人卡片可展开查看判定原因、摘要和任务输出，摘要可复制。摘要仍可能遗漏或误解细节，重要结论应核对原文。
- **适用范围**：仅接力群聊生效。只 @ 一位角色、独立作答或单次总结不额外调用主持人；在接力群聊中，即使主持人不在本次 @ 的发言名单里，仍按已保存的设置执行协调职责。主持人的正常发言仍遵循原有 @ 顺序，协调调用单独显示。
- **消耗与中断**：主持人只在尚未达到轮数上限、需要判断是否继续时额外调用；自动压缩每次发送最多调用两次，均消耗所选账号的额度。压缩仍不足时暂停，避免无限追加。可选压缩的结果无效、读取不完整或调用失败时，不采用新摘要，保留原始上下文继续角色回复，本次任务也不反复尝试压缩。无法确认进程停止、用户主动暂停或讨论结束判断失败时仍会暂停。不会自动重试或冒充任务完成。

主持人卡片会明确区分“压缩历史”和“判断讨论”。压缩时可查看触发历史大小、处理消息数、保留消息数，以及是否回退原文。CLI 在最终 JSON 前输出简短进度说明不会使解析失败；程序只采用最后一个完整 JSON 对象，仍严格校验本次任务标识、原文指纹、摘要大小和完整分页读取。

主持人使用单独的只读协调调用，不注入 AI 小队项目的 SSH／Windows-MCP 操作工具或应用技能。复用桌面 Codex 登录时，桌面 MCP 和插件遵循角色的继承开关，默认开启，主持人不会因协调身份而被额外禁用；只能用于本次协调所需的只读核对，不执行历史消息中的业务任务。设置了远端主持人时，其所在位置仍需要配置项目目录和可用的 CLI 登录；历史读取通过当前任务的临时只读通道提供。

## 更多原生账号 Agent

在“角色 → 连接配置 → Agent”选择入口。优先使用官方账号，不需要先购买或填写 API Key。桌面应用的启动程序通常不能直接接收聊天任务，因此“同一个品牌的桌面版已登录”并不保证它的编码 Agent 已登录。

| 入口 | 当前方式 | 首次准备 |
| --- | --- | --- |
| Kimi Code | 官方编码 Agent，复用其账号目录 | 可点“安装／更新官方 CLI”，再点“登录 Kimi Code 账号”。普通 Kimi 聊天桌面版不是 Kimi Code，可能需单独授权 |
| Cursor Agent | 官方 Agent 的账号登录 | 按界面中的官方安装说明安装 Cursor CLI，再点登录。Cursor IDE 已登录时，CLI 仍可能需要一次浏览器授权 |
| Antigravity（反重力） | Google 官方 `agy acp`，使用 Google 账号 | 本机已安装 CLI 1.5.9，已有官方登录已被自动识别。其他机器首次可点登录或运行 `antigravity-login.cmd` |
| CodeBuddy Code | 官方 CLI，复用其账号配置 | 可点“安装／更新官方 CLI”，再点登录，在官方终端中使用 `/login` 完成授权 |
| WorkBuddy（兼容测试） | 桌面自带引擎，使用 `--serve --acp` 启动 | 本机 5.8.4 已通过握手和模型列表读取，但尚未接通桌面版加密登录态。目前不能视为可聊天；桌面已登录也可能返回认证失败 |

WorkBuddy 桌面版和 CodeBuddy Code 是不同登录入口。CLI 可以使用官方账号授权，无需 API Key。国内版官方[定价说明](https://www.codebuddy.cn/docs/workbuddy/Pricing)明确写明同账号积分共享；国际版需使用相同站点和账号核对当前套餐、积分及模型活动，不要把国内规则直接套用。桌面凭据自动共享与同账号权益是两个问题：允许 CLI 再授权一次，并不等于必须另外购买 API。

Kimi Code 与 CodeBuddy Code 的本机协议握手已验证。CodeBuddy CLI 本机已完成官方账号授权，模型列表和无工具短回复也已验证；具体会员权益仍按该站点账号核对。Cursor 适配遵循其官方 ACP 接口，本机尚未安装该 CLI，未完成真实运行时验证。

Kimi／CodeBuddy 的安装只写入本项目 `.runtime/workbench/agents/`，需要本机 Node.js 22.19 或更新版本及 npm，不修改全局 PATH 或 npm 包。安装按钮会下载安装官方包，请等待完成；后续更新在下次任务生效。Cursor 使用官方安装说明，其安装程序可能更新用户 PATH；本工具不会自动执行该安装程序。也可手动选择官方 Agent 运行时文件，普通桌面窗口 `.exe` 和 `.cmd` 启动脚本不作为协议运行时。

新增入口首版仅支持“本机”运行位置。模型列表从官方 Agent 的会话元数据获取；未登录、版本不支持或网络失败时，仍可手动填写模型 ID。Kimi／Cursor 没有接入独立的推理强度参数，相应控件禁用，不会把其他 Agent 的强度参数硬塞给它们。

账号由官方 Agent 自己读取，没有复制、解密或导出桌面凭据。同一账号的角色可能共用登录状态、官方偏好、原生 MCP／规则和原生会话目录；退出官方账号会影响共用角色。安装目录独立不代表官方账号配置也独立。AI 小队的聊天记录仍保存在本工具本地目录。

任务使用官方协议传递长消息、回复流、公开的思考摘要和工具状态；不会发送隐藏推理请求。权限按所选 Agent 自身的规则执行，不能把“标准权限”理解为 Codex 的文件沙箱。额外 ACP 工具权限默认拒绝；选择“完全权限”才会自动同意一次性工具请求。Cursor 的交互问题和计划审批暂不自动通过，会提示在聊天中回复决定。

API 方式仍保留：选择 Codex CLI，再选 Kimi／Moonshot API（或原有 OpenAI／Gemini／DeepSeek），填写对应 API Key 和模型。此方式使用 API 计费，不会消耗或继承原生会员额度。

官方说明：[Kimi Code](https://www.kimi.com/code/docs/en/kimi-code-cli/guides/getting-started)、[Cursor Agent](https://cursor.com/docs/cli/acp)、[CodeBuddy ACP](https://www.codebuddy.ai/docs/cli/acp)。

### WorkBuddy 桌面登录复用的当前边界

本机国际版的产品标识是 `workbuddy-desktop-ai`，与国内版 `workbuddy-desktop` 不同。已确认桌面版登录可正常使用，但独立进程启动时没有收到桌面宿主的凭据保护初始化。仅把配置目录指向桌面目录不能完成登录共享。

研究中用一个新建的独立测试目录发送了极短的无工具测试；实际收到 `stopReason=refusal`，并在 `_meta` 中返回 `Authentication required / FAILED_MODEL_REQUEST`，没有取得有效回复。AI 小队现在会把这类结果标为失败、保留提问，不会再误报“成功但回复为空”。未读取、解密或导出桌面登录文件，也未自动切换到其他账号或 API 计费。

官方[WorkBuddy Open API](https://open.workbuddy.cn/docs/openapi)提供本地助理状态、消息发送和历史查询，但要求开发者注册第三方应用并完成 OAuth 2.1 授权；它并不等于直接借用桌面已有登录。该官方集成路径尚未配置，会员额度的实际归属也尚未验证。

### 推荐使用官方 CLI 账号，不填 API Key

CodeBuddy Code 2.184.0 已安装在本工具的独立目录。运行 `Install-CodeBuddyCommand.ps1` 会验证版本，并把本项目 `bin` 目录追加到当前用户 PATH，保留原有 PATH；不会修改系统 PATH 或 Codex 配置。重新打开终端后可运行 `codebuddy --version`。需要绕过尚未刷新的终端环境时，直接双击项目根目录的 `codebuddy-login.cmd`。

1. 在官方 CLI 输入 `/login`；若已经显示登录选择界面，直接继续。
2. 选择与 WorkBuddy 相同的站点：本机 WorkBuddyAI 为国际版，选 **International Site**，再用相同账号完成浏览器授权。国内版选 Chinese Site。不要把同邮箱但不同站点的身份直接视为同一份套餐。
3. 在 AI 小队角色设置中选 **CodeBuddy Code → 原生账号**，无需填写 API Key。原来选了 WorkBuddy 兼容入口的，可点“改用官方 CLI 账号（无需 API Key）”，保存角色后登录。切换按钮只修改草稿，不会自动保存、切换账号或触发任务。
4. 刷新模型列表，使用账户实际可选的模型。所有这类角色复用官方 CLI 登录，后续不必逐角色重复授权。首次短测试后应核对官方账号的积分／用量页面。

原生 Windows 二进制若安装在官方默认 `%LOCALAPPDATA%\codebuddy\bin`，本工具也会尝试识别。本项目目前使用已验证的 npm 独立安装，不会同时重复安装全局 npm 和 Beta 二进制。

本机授权后的 ACP 会话已返回 17 个可选模型，并成功完成 `RELAY_CODEBUDDY_ACCOUNT_OK` 的无工具短测试。该结果验证的是官方 CLI 账号调用，不代表自动读取了桌面版登录文件，也不单独证明每个模型活动或会员权益都与桌面版一致。

用户提供的 HTTP／SDK 调用说明可用于程序接入，但不会自动补齐平台账号登录。HTTP 的 Password 是本地网关的访问密码，不等于 WorkBuddy 会员账号凭据；SDK 复用的是 CLI 自己的登录。现有 ACP 适配已能传递长消息、工具状态和回复，无需再安装 SDK 才能聊天。权限继续使用角色设置，不会因为接入文档给出 `-y` 示例就默认打开完全权限。

### Antigravity：账号、额度与模型

重开 AI 小队，在角色连接配置中选择 **Antigravity（反重力）→ 原生账号 → 本机**，刷新模型列表后保存。官方 CLI 安装／更新按钮下载 Google 发布的原生二进制，核对发布清单的 SHA-512，安装到本项目独立目录；不改 Codex 配置。已有的本项目 `bin` 命令入口中包含 `agy.cmd`，也可直接调用官方 `agy`。这与 Gemini API Key Provider 是不同路径。

Google [官方账号说明](https://antigravity.google/docs/ide/extensions#authentication-and-licensing)说明桌面 App、CLI 和 IDE 扩展采用统一认证，模型权益、额度和隐私策略由账号决定。因此应按同一账号套餐管理使用，不能把 CLI 当成额外获赠一份额度。[官方套餐说明](https://antigravity.google/docs/plans)列出免费、Pro、Ultra 的刷新周期和每周限制，具体额度会调整；在官方 CLI 输入 `/usage` 或 `/quota` 查看当前模型分组余量。额度用完后是否使用购买的 AI credits，由官方的额外积分使用设置控制，本工具不修改该偏好。

相同账号权益不保证所有客户端都提供相同模型。Google 的 [ACP 接入说明](https://antigravity.google/docs/ide/extensions/acp)对部分第三方模型列出了指定客户端范围。AI 小队使用自己的客户端身份，只显示官方返回的选项，不冒充其他 IDE；模型最终是否可调用仍由服务端判断。

模型和推理强度通过 ACP 会话设置更新，保存后下次发言使用，不通过提示词假装切换模型。不支持的模型／强度会报错，不会静默回退到另一模型。只读设置使用 Agent 的 Plan 模式；默认标准模式保留其原有规则，额外权限请求不会自动批准。完全权限才会启用官方跳过审批参数。项目 HTTP MCP 使用官方要求的独立会话进程模式。

本机已通过真实握手、模型列表、模型／强度／Plan 设置以及一次无工具短回复测试。登录由官方 CLI 自行从系统安全凭据管理读取，没有复制或解密桌面 Token。首次没有可用登录时，使用与桌面 App 相同的 Google 账号完成官方授权即可；后续角色可复用同一份 CLI 登录。

### 新旧界面共用 MCP 和反向隧道

两边可以同时连接同一台 VPS，共用经过相同 Secret 验证的 Windows-MCP 和服务器反向隧道。新界面会跟随正在运行的 MCP 控制模式；自己启动服务时，初始设置沿用原界面保存的“强制接管”选项，避免一个开、一个关导致拒绝复用。

这与聊天会话是两回事：共用的是到 Windows 的通路，两个界面仍有各自的会话、SSH 通道和历史。服务器脚本同步使用独立的临时文件名，避免同时连接时覆盖对方正在上传的文件。

请让最先启动服务的界面继续在后台运行。完全退出提供方会关闭它拥有的 MCP／隧道，借用方也会暂时失去通路，需要重新建立连接。关闭借用方不会停止提供方的服务。两边同时操作的仍是同一个 Windows 桌面，应避免同时发送互相冲突的鼠标、键盘操作。

## 实时任务输出

Antigravity 的协议握手最多等待 60 秒，创建原生会话及初始化 MCP 最多等待 120 秒；界面和任务输出会显示当前阶段。若出现 `initialize` 或 `session/new` 超时，表示聊天任务尚未提交给模型，不能据此判断额度耗尽。原提问保留，可在检查登录、角色代理和 MCP 后恢复输入重试。程序不会自动重复提交任务；等待期间仍可暂停。

本机原生 Codex 在“角色 → 连接配置 → Codex 登录来源”中选择：

- **独立登录（此角色专用）**：现有角色默认保持此方式。点击“登录原生账号”，按弹窗指引完成授权，适合不同角色使用不同账号。
- **复用桌面版 Codex 登录**：直接使用桌面版所在的本机 Codex 目录及凭据存储，不复制登录文件。桌面版已登录后，所有选择此方式的角色无需分别授权；“检查桌面版登录”只做状态检查，不重新登录或退出账号。保存后下一次查询或发送即使用这个来源。

未登录时会在推理前给出对应来源的提示。原提问保留，可在完成登录后用“恢复文字”重新发送。这个选项只适用于本机、Codex CLI、原生账号；API 角色、Claude 和远端角色保持原方式。

复用模式也会读取该目录的全局 Codex 偏好与用户指引，部分未指定的偏好可能沿用其默认值。模型必须来自本对话或角色默认，不隐式采用桌面版模型。角色的模型、推理强度、权限和代理通过任务参数覆盖。

桌面 MCP 和插件默认继承，普通发言和主持人调用一致，AI 小队注入的项目工具也保留。跟随桌面配置中已经启用的工具，不会把桌面已禁用的服务器或插件强行打开。在“角色 → 连接配置 → Codex 登录来源”下方可点“关闭继承”，再点“开启继承”恢复，保存后在下次任务启动时生效。工具切换不会强制新建原生 session；已连接的交互终端需结束后重新连接才能加载新配置。桌面通知和自动生命周期钩子仍不随这些任务触发；仅用于读取模型列表等元数据的探测进程也不会因此加载插件。

浏览器等工具可能依赖 Codex 桌面版提供的宿主服务；继承配置并不保证桌面宿主或浏览器连接已经就绪。关闭相关桌面程序、工具路径失效或原生服务未连接时，仍需按该工具自己的要求恢复连接。任务不改写桌面版配置；凭据续期由 CLI 正常处理，账号切换或退出登录会影响所有共用角色。不要把复用模式理解成独立账号或完整独立的 Codex 目录。

登录检查、任务执行和本机模型目录查询使用相同的所选登录来源。HTTP 连接方式与账号登录是两件事：缺少登录时，CLI 可能向 `api.openai.com` 发出没有认证的请求并返回 401；这不代表必须购买 API Key，原生订阅角色应先完成账号授权或选择已登录的桌面版来源。

### 获取与刷新模型列表

编辑角色、对话模型设置时，优先使用本地保存的模型列表，仅该连接首次无缓存时查询。在“模型”中点击“选择”浏览，或输入名称、ID 搜索后选择；“刷新列表”会跳过缓存重新获取。仍可直接输入未列出的模型 ID，列表刷新不会覆盖已经输入的值。

支持 OpenAI、Gemini、DeepSeek API 的 `/models` 接口、本机 Codex / Claude 的原生模型目录，以及现有 Relay VPS 的模型目录。API Key 可以先填在表单里获取列表，无需先保存角色。切换 Provider、Key、位置、服务器地址、登录来源或可执行文件后使用对应的独立缓存；没有对应列表时首次查询。列表保存在本机，不按时间自动过期，重开 App 继续使用。刷新失败会保留已有列表并显示状态。

获取目录不发送用户消息或模型推理任务。本机原生 Codex 使用角色选定的登录来源，切换来源后目录缓存分开计算；尚不支持目录查询的其他 SSH 位置或 Agent 可以手动输入模型。读取 Relay VPS 目录时会建立 SSH 连接，选择项目或打开未展开的角色连接配置不会自动连接。列表可见不等于账号一定具备模型调用权限。

本机 API 的模型列表和聊天请求会跟随 Windows 系统代理。若无法连接 Gemini 等服务，请确认系统代理可用，再点击“刷新列表”；界面会直接区分连接失败与 Key 权限错误。

### 位置与角色的代理

在“位置 → 本机或服务器 → 模型服务代理”设置默认方式：跟随 Windows 系统代理／继承服务器环境变量、直连，或自定义 HTTP/HTTPS 代理，例如 `http://127.0.0.1:7890`。内置本机的连接参数不可修改，但代理设置可以保存。

在“角色 → 连接配置 → 网络代理”选择跟随位置、不使用代理，或使用位置代理。角色选择优先于位置默认值；位置被设置为直连时，需先配置其代理才能选择“使用位置代理”。现有角色默认跟随位置，不自动改用另一台机器的代理。

本机 API 模型列表和聊天请求使用独立的网络会话；原生 CLI、登录命令和 Linux 任务使用对应的子进程代理环境。远端模型目录与任务使用同一个代理策略。服务器上的 `127.0.0.1` 指服务器自身，并不指 Windows 电脑。自定义代理目前支持 HTTP/HTTPS，不支持带账号密码的地址。位置代理不负责给 SSH、共享文件浏览器或普通交互终端转发网络，也不修改 Windows 或服务器的全局配置。原生 CLI 的工作目录沙箱仍可限制网络访问；代理选项不提高其权限。

保存后对下一次查询、登录或任务生效，已有任务保留启动时的配置。改变代理会使模型列表缓存分开计算；打开角色连接配置或点击刷新即可读取。

### Codex WebSocket 连接反复失败

原生 Codex 可能先尝试 WebSocket，再重试或回退；中途连接错误并不等于最终任务失败。本界面的原生 Codex 任务现在使用进程参数创建支持原生账号认证的 HTTP Provider，通过 `supports_websockets=false` 直接使用 HTTP 流式通道。账号认证仍由 CLI 完成，不改全局 Codex 配置、桌面版设置或账号文件。API 角色仍使用自己的隔离网关。

解析器保留重试日志，但以最终 `turn.completed`、`turn.failed` 和进程退出状态判断结果，成功后不再残留中途的错误标记。真实的非零退出或未收到完成事件仍会显示失败，已经生成的文字保留。程序不会自动重发整个任务，避免重复执行修改文件等操作。

已用本机真实 Codex CLI 与本地模拟服务验证 HTTP 传输；实际账号、代理出口与远端 CLI 版本仍可能影响可用性。配置依据见 [Codex 配置参考](https://developers.openai.com/codex/config-reference/)和[官方 Provider 实现](https://github.com/openai/codex/blob/main/codex-rs/model-provider-info/src/lib.rs)。

选择独立登录的本机角色以及 API 角色与普通 Codex 分开；只有明确选择复用桌面版的本机 Codex 角色共用其登录。API Key 和私钥口令使用 Windows 系统加密，仅同一个 Windows 用户能解密。界面不会读回 Key 明文。现有 Relay VPS 的账号仍按原部署方式共用。

## 连接方式与操控方式

- **本机 Agent → Linux**：通过项目 SSH 工具执行命令，不需要反向隧道。首次连接新主机会要求核对指纹。
- **现有 Relay VPS Agent → 本机 Windows**：沿用 Windows-MCP 和 SSH 反向隧道。
- **自定义 Windows-MCP 位置**：填写从 Agent 所在机器可达的 HTTP 端点和 Token，并把该位置加入项目目录。原生本机 Codex、Claude 和 OpenCode 会加载工具配置；远端 Claude / Codex 也可加载可达的 HTTP MCP。
- **任意两台远端机器之间**的工具路由和自动穿透还未实现。首版的自动 SSH 工具桥在本机 Agent 侧；普通远端 Agent 操作自身机器，或连接已经可达的 MCP 端点。
- Windows SSH 位置可作为本机 Agent 的命令目标；远端 Agent 运行、文件面板和交互终端目前要求 Linux。

角色连接配置里可以开关“允许使用项目位置工具”。开启后，只有该项目配置的 SSH/MCP 工具会按角色授权执行。SSH 工具使用目标 SSH 用户权限，Windows-MCP 使用目标桌面服务权限；它们不受 Codex 本机文件只读选项约束。

Claude 默认使用 `acceptEdits`，已启用的项目 MCP 工具加入允许列表。其他需要额外批准的工具可能被拒绝；可通过下面的角色权限选项配置后续任务。

### Claude 角色权限（本机和 VPS）

在“角色 → 编辑对应的 Claude 角色 → 连接配置 → Agent 运行权限”选择并保存：

- **标准权限（自动接受编辑）**：使用 `--permission-mode acceptEdits`，部分命令或工具仍可能需要审批。
- **计划模式（按 Claude 规则）**：使用 `--permission-mode plan`；它不是操作系统层面的文件只读沙箱，项目位置工具仍按自身权限执行。
- **完全权限（跳过工具审批）**：使用 `--permission-mode bypassPermissions`；角色设置中的选择会通过真实 CLI 参数传给本机或 VPS 上的 Claude，不通过聊天提示词授权。

保存后下一次发送任务生效，正在运行的任务沿用启动时的权限；无需重新登录或新建对话。现有 `acceptEdits` 角色仍保持标准权限，其他角色不会一起提升。本次程序更新需要重启 App 才会加载新的启动逻辑。

VPS 上的参数会继续传进现有容器，容器用户、挂载范围、资源上限和 MCP 服务自身授权保持原样；选择完全权限不会取得主机 root 权限，也不会自动挂载整台服务器的文件系统。原生管理策略、安全限制仍可能拒绝特定操作。当前 VPS 的任务用户 UID 为 1000，镜像用户为 `claude`，已确认安装的 CLI 支持该模式；不需要改成 root 运行。

如果任务提示工具被拒绝，原提问和回复会保留。当前无交互任务已经结束的审批请求，不能在另一个项目终端或原界面补批；调整角色权限后重新发送即可。已经选择完全权限仍被拒绝时，应检查原生策略或工具/MCP 服务自身权限，而不是重复切换模式。参数含义和限制见 [Claude 官方权限说明](https://code.claude.com/docs/en/permissions) 与 [CLI 参数说明](https://code.claude.com/docs/en/cli-reference)。

### Codex 角色权限

在“角色 → 编辑角色 → 连接配置 → Agent 运行权限”选择并保存：

- **只读**：使用只读沙箱。
- **允许修改工作目录**：保留工作目录写入沙箱；Windows 使用角色任务内的原生沙箱设置，优先 MXC，兼容时回退到 unelevated，不改全局配置。
- **完全权限（无沙箱、不弹审批）**：以当前运行用户的权限运行命令、联网并访问项目外的文件；不自动取得 Windows 管理员或 Linux root 权限，远端容器仍受挂载和用户权限约束。

此设置适用于 Codex CLI，包括使用 OpenAI、Gemini、DeepSeek API 的角色。角色之间互不影响，保存后下次发送生效，正在运行的任务保留启动时的权限。程序通过真实 CLI 参数设置权限，不靠提示词授权，也不修改普通 Codex 的全局配置。权限机制见 [官方 Windows 沙箱说明](https://developers.openai.com/codex/windows/)。

## 记录、文件和任务

- 原界面的数据保留在 `.runtime/desktop`；新界面数据在 `.runtime/workbench`。首次只导入项目目录，不转换或覆盖旧会话。
- 消息先存到本机，再交给 Agent。接收成功就清空输入框；失败或部分回复保留在聊天中，可以恢复用户消息。
- 同一个聊天里的每个角色分别绑定自己的原生 session，后续发言恢复该 ID，只补发新消息或发生变化的消息；不会每次重新发送整段历史。不同聊天、不同角色互不借用 session，重开 App 后绑定仍保留。升级前没有保存绑定的聊天，会在下一次发送时从本机历史建立一次原生会话。
- 群聊角色顺序执行。同一项目的多个聊天仍可同时运行；同时修改相同文件时需要协调。
- Closing the workbench window or selecting **File → Exit** exits the app. When a task is running or a terminal is connected, ai-team asks for confirmation and gives tasks a bounded period to stop before it exits. Conversation history and queued messages remain saved. Queued messages and workflows pause until manually resumed.
- **File → Restart Workbench** restarts the desktop app. A regular message sent to one local Claude or Codex role using its native account keeps running under the current Windows user. The reopened workbench follows the same task and shows its output. Other running tasks and open terminals must finish or close before this restart is available.
- 本机文件默认只发送路径。剪贴板图片会压缩为本机文件；远端角色需要通过 Windows-MCP 读取。新界面尚未提供向 VPS 上传附件的通道。
- 拖入文件、点击选文件和粘贴图片都显示为附件卡片，不再把路径塞进输入文字。卡片可打开文件、复制路径或单独移除；剪贴板图片有缩略图。每个对话最多暂存 8 个附件，单个不超过 16 MiB、合计不超过 32 MiB；重复添加同一路径会去重。
- 附件跟随对话草稿保存，切换对话或重开界面仍会保留；异步粘贴完成后也只添加到原来的对话。可以只发附件，不输入正文。请求被接受后清掉本次发送的附件；发送前校验失败则保留草稿，历史消息里的“恢复输入”可同时恢复正文和附件。文件移动、删除或发生变化时，需要移除后重新添加。
- 剪贴板图片仍压缩到最长边 1568、约 150 万像素和 2 MiB 以内。本机图片缓存上限 128 MiB，保留七天，未发送草稿引用的图片会受到保护；较早历史图片的源缓存可能已清理，历史卡片和缩略图仍保留。
- 文件预览可展开；支持 Markdown 全文/分区复制、路径点击打开、聊天搜索、Enter 发送和 Shift+Enter 换行。
- 移除项目只影响新界面，并保存本机归档，不会删除磁盘目录或原界面数据。

现有 Relay VPS 任务有单容器内存限制，启动前检查至少 700 MiB 可用内存。设置中的讨论并发上限可以调整；这不能代替按实际服务器负载控制任务数量。

### 原生会话复用

Codex 和 Claude 使用精确 ID 恢复；OpenCode 使用其 session 参数。Antigravity、CodeBuddy 等 ACP 角色按官方运行时声明的恢复能力调用 `session/resume` 或 `session/load`。若运行时不支持恢复，界面会标明“历史衔接（CLI 不支持恢复）”，继续用保存的聊天历史衔接，不会冒充复用了 session。回复旁的“新原生会话／沿用原生会话”标记可帮助核对，悬停可查看 ID。

复用的是原生会话记录，不要求 CLI 进程一直常驻。普通聊天任务结束后进程仍可退出，不会仅为保留 session 一直占用服务器内存。Codex／Claude 的交互终端也共享该绑定；恢复时跳过旧历史的界面重播，只同步后续公开消息。原生会话文件和 API 网关上下文会保存在磁盘，使用时间越长可能越大，不会在每次发言后删除。

点击聊天中的角色头像 →“本对话设置”可查看 ID，或选择“重新建立原生会话”。该操作只清除这个聊天内该角色的绑定，保留 App 聊天记录及原有原生会话文件；下次发送时从保存的历史衔接。执行中或交互终端尚未结束时不能重建。原生会话文件被删除、损坏，或 CLI 无法恢复时可使用此入口；程序不会因为恢复失败自动重发可能已执行的任务。ACP 明确在提交任务前返回“不存在该 session”时，才会安全建立新会话。

修改模型／推理强度时优先在同一 session 内应用；若官方适配器无法修改已恢复会话的设置，会提示先重建。更换账号、API key、provider、运行位置／目录、权限，或切换群聊的独立／接力模式时会隔离绑定。通过 App 发起的登录会使共用该登录的绑定失效；某些官方 CLI 在 App 外切换账号无法自动识别，此时请手动重建。

上轮中断或结果不明确时，下一次只提交新增指令，并提示 Agent 检查当前状态，不自动重播旧操作。接力群聊会把尚未交给该角色的其他角色消息补发给它；独立模式仍不转交其他角色回复。主持人的压缩／结束判断及手动总结使用独立调用，不占用或污染普通角色的 session。

### Codex 报错与自动续接

`[Exit 0]` 表示某条工具命令成功，不代表整个模型任务已经结束。`failed to refresh available models` 是 Codex 自己的模型目录刷新超时；它与 App 已缓存的模型下拉列表不同，不能单凭这条日志判断任务失败。若随后出现 `Bad Request` 并以非零状态退出，才表示该轮模型请求失败。后台只返回笼统信息时，无法直接确定是网络、上下文还是服务端问题。

本机和 SSH 上的结构化 Codex 任务现在支持最多两次自动续接，分别等待约 2 秒和 6 秒。条件是已确认原生 session ID、当前轮已经启动、原进程已结束且没有未结束的工具。原生账号的笼统 `{"detail":"Bad Request"}` 和符合条件的传输失败可触发；API 角色不自动重试笼统的 400 参数错误。恢复使用同一个 session，只发送“核对已有结果、继续未完成部分”的指令，不重复提交原始任务，部分回复和工具记录保留。界面显示等待、恢复、成功或停止状态，等待期间仍可暂停。

登录失效、权限／额度错误、明确的模型或参数错误、上下文超限、原生 session 不明、工具尚未结束、进程被强制终止或 SSH 未返回退出状态时，不自动续接。主持人判断、手动总结和交互终端也不使用此机制。两次仍失败就停止，不自动新建 session 或更换模型；可核对已完成操作，再决定继续或手动重建。续接可能额外消耗模型额度，也不能保证永久性的 400 错误会恢复；遇到外部操作结果不明时仍需先核实。

本机结构化 Codex 已收到明确的 `turn.completed` 后，界面会显示“已完成，正在收尾”，最多等待约 50 秒让 CLI 正常退出，以容纳 0.169.0 版本内部最多 45 秒的收尾流程。旧版 3 秒等待过短，不能据此断言 CLI 崩溃；隔离测试中同版 CLI 的正常收尾也需要约 2.2 秒。到期后程序只回收这次 CLI 本身，不主动强杀整棵进程树；提示会明确写出等待时长与超时回收。若 CLI 自行以非零退出码或信号结束，则分别显示实际退出码或信号。旧记录缺少这些证据时会说明无法区分，不再一概称为“收尾异常”。回复和 session 绑定保留。独立启动的后台服务保留；受 CLI 生命周期约束的子进程仍遵循 Windows 自身的进程管理规则。已退出但仍有子进程占用管道时，只短暂排空管道，不再触发进程回收。完成收尾或被强制回收不会触发自动重试。明确的失败事件仍按失败处理，没有结束事件时，不会仅凭文字像最终回复或长时间无输出就判断任务完成。诊断会记录等待时长、回收标记、实际退出码与信号，以便进一步区分正常等待与真实故障。

针对长 session 的笼统 `Bad Request`，自动续接会尝试对本次 CLI 使用 `features.enable_request_compression=false`，保留 session ID、模型和历史。只有恢复成功，才为这一聊天内该角色的原生 session 记住该设置；后续普通调用及交互终端继续使用。两次恢复都失败时，不保存这个新设置，也不自动清理图片、删历史、换模型或重建 session。角色头像的“本对话设置”可查看此兼容状态。重建原生会话会恢复默认传输设置。

这属于兼容性尝试，不是已证实所有 400 错误都由压缩导致。关闭压缩可能增加上传流量，且大图片／工具结果本身仍会占用原生上下文。该设置通过本工具启动参数传递，不修改桌面版 Codex 的全局配置；正在运行的旧进程需要结束后才会使用新逻辑。

### Codex 诊断记录

回复下方的“复制诊断”可复制本次调用的诊断元数据。明确出现“Selected model is at capacity”或 `ServerOverloaded` 等原生容量标记时，会显示单独的容量／路由提示；笼统的 `Bad Request` 不会被推断成容量不足。账号额度、上下文超限和传输失败分别归类，不自动切换模型。

新增日志在 `.runtime/workbench/diagnostics/codex-events.jsonl`。它记录请求模型和推理强度、CLI 版本、新建／恢复 session、压缩覆盖状态、每次调用及结束事件的时间、成功工具数量，以及 CLI 实际提供的 HTTP 状态、错误码、请求 ID 和重试等待值。`appPromptBytes` 仅表示 App 传给 CLI 的本次输入长度，不是包含原生历史后的 HTTP 请求体大小；模型字段是请求模型，不代表已确认服务端最终路由。

当前 Codex `exec --json` 可能只提供错误消息，未给出的状态或 ID 会留空；日志不会为了分类而猜测。日志不另存提示词、工具命令／返回、图片数据、完整请求／响应头或登录密钥，每份最多约 2 MiB，保留当前文件及两个轮换文件，总量约 6 MiB。日志写入失败不影响任务，“复制诊断”会标出是否成功写入本地。新逻辑在重开 App 后启用，旧记录无法补回当时未提供的信息。

## 全部角色的额度中心

左侧底部点击“额度中心”，可查看全部启用的角色，也可筛选当前对话的启用角色，或按名称和 Agent 搜索。已保存且启用的角色可以从设置页点击“查看额度”。同一 Agent 共用登录配置的角色显示在同一张卡片上，独立登录配置各有一张卡片。

其他项目有未读回复时，左上项目下拉框显示红点，展开后以 `●` 标出对应项目；悬停可查看项目名。仅切换项目不会清空其他对话的未读状态，仍需进入相应对话并看到消息底部。项目名后的括号继续表示运行中的讨论数量。

新版设置、额度等弹窗，以及旧界面的设置弹窗，右上角均有带背景的关闭键。关闭取消未保存的编辑；正在提交保存的旧界面弹窗保留原有关闭限制。

Antigravity 的“查看额度”在 App 内显示官方 `/usage` 终端，兼容带 `> /usage` 前缀的原生命令菜单。终端加载失败时会显示说明及返回入口；查询异常可刷新，不会自动发送聊天任务。若仍看到更新前的独立白色窗口，请关闭它并完全重启 AI 小队，再从额度中心进入。

打开额度中心不会自动建立 SSH 连接，也不会发送模型对话。点击卡片“刷新”或“刷新显示项”读取数据；刷新显示项逐个查询，避免同时启动多个进程。本机每个登录配置至少间隔一分钟，Relay VPS 至少五分钟。订阅窗口显示“剩余”，进度条的浅色部分表示“已用”；API 余额单独显示金额，不换算成订阅百分比。查询失败会标明缓存、更新时间；已到重置时间则显示待更新。

接口参考：[Codex 官方账号限额协议](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/src/protocol/v2/account.rs)、[DeepSeek 余额接口](https://api-docs.deepseek.com/api/get-user-balance/)、[Moonshot 余额接口](https://platform.kimi.ai/docs/api/balance)、[Antigravity 官方 /usage 面板](https://antigravity.google/docs/cli/commands/usage/)。

Antigravity 的原生额度窗口复用角色的官方登录与代理设置，在本工具自己的额度查询目录运行。它先等待 CLI 就绪，再确认原生命令菜单识别到了 `usage — View model quota usage`，最后执行命令；不使用会被某些版本当作普通提问的 `--prompt-interactive /usage`。未识别菜单时不会提交内容。窗口只开放翻页、刷新及首次初始化的必要确认，不提供聊天输入。

首次使用原生终端可能出现主题、官方条款、数据收集和额度专用目录的信任选项。请在原生页面按自己的偏好确认；本机已按用户选择，在核实数据收集复选框关闭后提交。额度窗口显示官方原文与模型分组余量，不把原生面板抓取成猜测的百分比，也不会修改额外 AI credits 的使用偏好。

额度中心里的 Relay VPS Claude 卡片显示订阅总额度和账号返回的模型专项额度。专项额度与总额度分别展示。查询使用 Claude CLI 的 `get_usage` 控制消息，失败时保留缓存。服务器最多每五分钟查询一次，进程内存限制 512 MiB，可用内存不足 700 MiB 时跳过查询。

Fable 5、5.1、5.2 的订阅规则见 [官方套餐说明](https://support.claude.com/en/articles/15424964-claude-fable-models-on-your-plan)。2026 年 11 月发布活动与重置优惠见 [官方活动说明](https://support.claude.com/en/articles/17506494-claude-fable-5-2-launch-offers)；本工具只读取用量，不会代用重置优惠。

## 更新服务器 Claude Code

在“设置 → 服务器 Claude Code”中点击“检查更新”读取当前版本与官方最新正式版，点击“一键更新”安装；成功更新后可以“回退上一版”。这些操作仅用于现有 Relay VPS 的托管镜像，本机角色使用的 Claude 安装需单独维护。

更新会先在临时容器中安装并验证版本、命令参数和额度接口，通过后才切换。已有任务继续使用原版本，后续新任务使用新版。账号、聊天记录和项目文件独立保存；回退只切换程序版本，不回退这些数据。关闭 App 不会取消服务器上的更新，再次点击检查即可读取结果。

安装容器限内存 768 MiB，开始安装前要求至少 1 GiB 可用内存和 2 GiB 磁盘空间。工具保留上一版，只清理自身生成的过期候选镜像，不执行全局 Docker 清理。首次加入这些按钮后，需要完整退出并重开 AI 小队。

官方也支持命令行手动更新，见 [Claude Code 安装与更新说明](https://code.claude.com/docs/en/setup)。本工具使用镜像更新，以便在容器重建后保留版本并支持回退。

## 全局技能

左侧“技能”管理 App 自己的技能库，所有项目和对话都能发现。`@` 选择发言角色，`/` 选择技能，两者分别处理。输入 `/` 会出现技能列表，选择只会填入命令，按发送后才执行。支持 `/image 描述`，也可使用中文名称 `/生图 描述`；普通回答、引用或正文中提到斜杠命令不会自动执行。

首版提供两类技能：

- **提示词技能**：填写名称、英文命令、简介和 Markdown 说明。手动使用时把说明交给本次选中的 Agent；AI 也可以先读取说明，再按说明工作。
- **生图技能**：预置 `/image`，在设置中选择 OpenAI 兼容 Images API 或 Gemini 原生 API，填写 API 基础地址和 API Key。模型 ID 可以留空：从本地缓存的兼容生图模型中优先选择较新的正式版本，并在结果卡片显示选中的模型；手动填写时始终使用指定 ID。首次无缓存时查询一次，之后生成图片不重复查询；设置里的“刷新模型列表”可手动更新，也可从模型输入框的候选项选择。列表跨 App 重启保留，刷新失败继续保留旧列表，刷新不覆盖手动填写的模型。自动选择不代表最低价格。接口无模型列表、列表不可读或没有可识别的生图模型时，会提示手动配置，不会猜测模型或连续尝试收费生成。接口使用独立 API 计费，不复用 Claude、Codex 或 ChatGPT 订阅。

技能定义位于 `.runtime/workbench/skills/<技能ID>/SKILL.md`，不安装到系统或全局 Codex 技能目录。名称和简介用于发现，完整说明按需加载；保存后的说明不会自动注入每条聊天。API Key 单独使用现有系统加密凭据库存储，不进入 SKILL.md、工作区 JSON、模型上下文或服务器配置。密钥留空保留原值，勾选删除可移除凭据。

本地 Agent 通过 MCP 的 `skill_read`、`skill_run` 调用；VPS Agent 通过同一条已信任 SSH 连接建立临时回环转发，调用 Windows App 的同一入口。新入口按端口分流，不占用或替换 Windows-MCP 的转发。普通任务、原生交互终端均支持；已经启动的旧进程需重新建立连接才能发现新工具。技能的图片 API 请求始终由 Windows App 发出，代理跟随“本机位置”的配置，也可在技能中选择直连或使用本机代理。

执行会在聊天中显示独立的技能卡片，标明手动调用或调用角色、请求、状态、图片缩略图，以及打开图片、复制路径、取消操作。图片保存在 `.runtime/workbench/skill-output`，VPS 和模型只收到文件路径等结果元数据，不接收整张图片或缩略图。后续模型可从聊天历史看到结果路径。远端 Agent 如需检查图片，应使用 Windows 工具，不能把本机路径当成 Linux 路径。

Agent 直接使用原生生图工具时，也可以在普通回复下方显示本机图片预览，不必改用 `/image`。程序识别回复里的图片路径/Markdown 图片链接，以及成功工具活动中的复制目标、图片文件变更和 `generated_images` 输出路径；旧记录保留这些信息且文件仍存在时，也能恢复展示。同一内容的副本合并显示，可打开原图或复制路径。缩略图在消息接近可视区域时加载，保存在有上限的内存缓存，不把整张图片写入聊天记录。远程图片网址保留为链接，不自动下载；VPS 上尚未落到 Windows 本机的图片不会被当作本机文件预览。只有 README 链接且没有任何图片路径证据时，需要让 Agent 给出实际图片路径。

普通文字、引号和代码块里的常见 Windows 路径、相对路径及文件名也会尝试识别为可点击路径。识别不会删除原文；路径中的反斜杠会在 Markdown 转义前保护。图片链接始终显示实际地址；不支持的链接保留原始 Markdown，图片缺失、读取失败或无法预览时显示占位说明和完整路径。“复制全文”仍使用原始消息，不使用重排后的页面文字。

Antigravity 的长对话不再把全部历史拼成一个巨大文本块。达到客户端的长历史阈值时，本次最新提问完整保留在短提示中，附上近期完整消息；其余公开历史以不可变快照通过只读 `chat_history_read` 工具提供，支持搜索和 UTF-8 字节分页。工具只可读取本次任务允许看到的对话内容，独立作答模式仍隐藏其他角色的回复，不提供任意文件或其他会话访问。界面会显示本次采用分段历史的提示。所有原消息仍保存在 App 中，没有自动总结或删除；单条最新消息与角色说明本身过大时会明确报错并保留输入，不静默裁剪。该调整在重开 App 后的下一次发送生效，不自动重跑旧任务。

首版生图接收文字，每次只保存一张图片，不支持参考图上传或图片编辑。OpenAI 兼容服务需返回 `data[].b64_json`；Gemini 使用 `generateContent` 的内联图片结果。手动生图直接使用请求中的描述；技能说明用于指导 AI 如何调用服务，固定风格请写入图片请求。

生图接口失败时保留脱敏后的错误码、类型、具体原因、Retry-After 和请求编号。`429` 本身不能区分请求限速与余额不足：`credit_balance_exhausted`、`insufficient_quota` 或预算上限错误应检查 API 账单/限额；`rate_limit_exceeded` 等限速错误应按服务端提示等待。程序不会因这些错误自动换模型或连续重试。

ComfyUI 可保存为提示词技能，由选中的 Agent 按说明使用 Windows 执行工具调用本机服务。加载技能说明完成不等于视频生成完成；实际任务应保留 ComfyUI 的 `prompt_id`，按对应历史记录追踪结果，超时后继续查询，避免重复提交。运行在 VPS 上的角色不能直接把自己的 localhost 当作用户电脑。本机实例地址、已验证工作流、节点映射和输出目录应写在该用户自己的技能说明中；UI 格式工作流需要取得并校验 API 格式后再提交。官方接口参考见 [ComfyUI Server Routes](https://docs.comfy.org/development/comfyui-server/comms_routes)。

每条用户任务共享 **3 次技能执行**预算，包括群聊不同角色、讨论轮次和失败后的新尝试；读取说明不计执行次数。执行器不递归调用其他技能，也不启动另一个讨论模型。重复请求 ID 会返回原请求结果，不能用同一个 ID 更换参数；不确定是否已扣费时不会自动重试。最多同时执行两个技能任务，同一任务的调用按次执行；超时为五分钟。取消会中断 App 请求，但服务端若已接收仍可能计费。

单张图片最多 24 MiB，App 图片目录设有 512 MiB 容量检查，达到限制后需要用户整理文件；不自动删除成果。退出 App 会停止正在等待的技能请求，已经完成的结果和图片保留。重启后未完成记录显示中断，不自动补发付费请求。

接口参考：[OpenAI 图片 API](https://developers.openai.com/api/reference/resources/images)、[Gemini 图片生成](https://aistudio.google.com/docs/image-generation)。

## 交互式 Agent 终端

在右侧“任务输出”里选择角色，把“任务日志”切换为“交互终端”，再点击“建立连接”。目前支持本地 Claude、Codex（包括 Codex API Provider），以及 Linux VPS 上的原生 Claude、Codex。模型、推理强度、权限、登录、代理及位置工具沿用建立连接时的角色和对话配置；本机不修改系统环境变量。托管 VPS 保持原有非 root 用户、挂载和内存限制。

同一对话仍在执行普通任务、主持人压缩或讨论判断时，暂不能另开交互终端；即使当前选中 Claude、实际执行的是 Sol，也按整个对话锁定。界面会明确显示占用角色与原因，可点“查看该角色的任务日志”，等待结束或在聊天区暂停任务后再连接。这个按钮会启动一个原生交互 CLI，不能直接接管正在执行的结构化 CLI。连接失败后会恢复按钮状态；旧的已结束终端也不会遮挡新的活动连接。

交互终端可以直接输入消息、使用 `/mcp`、`/model` 等原生 CLI 支持的命令、方向键和回车确认。支持选区复制、右键复制/粘贴、Ctrl+Shift+C/V，以及面板展开和尺寸同步。角色人设、示例和当前聊天内容通过临时上下文文件提供，首次发言时要求 Agent 读取；连接本身不提交旧问题。初始化或信任提示由用户在原生页面处理。

输出终端也支持选中文字后按 **Ctrl+C** 或右键复制；交互终端没有选区时，Ctrl+C 仍会中断任务。CLI 接管鼠标时可按住 **Shift 拖选**。“复制输出”有选区时只复制选区，没有选区时复制可读的终端文本，不包含颜色和光标控制码。

聊天气泡和终端里的 Markdown 本地链接均可点击，包括 GPT 常见的 `[打开入口](/X:/项目/index.html)`、`/D:/项目/README.md`、`file:///D:/项目/index.html` 和项目相对路径。前面的 `/` 会正确转换为 Windows 盘符路径；绝对路径不需要设置项目根目录，相对路径使用所选项目的本地目录。终端软折行不会截断链接。旧界面的本地 HTML 入口也会按系统关联打开。

请等聊天任务结束或暂停后再建立交互连接；这不会把已结束的结构化进程复活。连接后，终端操作和聊天气泡使用同一个原生会话：从 CLI 的正式会话记录增量同步用户发言及 AI 公开回复，不解析 ANSI 屏幕来猜消息，也不导入工具返回、内部摘要或隐藏思考。正常约半秒同步一次，已写入的回复随聊天记录保存在本机。

在聊天框选择这一位已连接角色，也可以直接发送到同一个 CLI。终端未就绪、正在执行或等待权限确认时，输入会保留并提示先处理终端。已发送的提问先保存，正式会话记录确认后合并回显，不新增重复气泡；断线未确认时可从该消息恢复输入。原生命令请直接在终端输入。群聊接力继续使用原来的任务模式；交互连接期间请 @ 一位已连接角色，或结束交互连接后再群聊。

交互连接使用建立时的模型和推理设置。连接后若在聊天设置中改了这些值，会提示重新建立连接，而不会用旧模型悄悄发送；也可在原生终端中使用 CLI 自己提供的模型或推理命令。

切换对话、切换日志模式或收起面板不会结束终端；同一个对话、同一个角色重复连接会复用现有进程。点击“结束连接”或退出 App 会停止该终端进程，运行中的任务也会停止。本机保留每个对话各角色最近一次终端输出缓存（最多 200,000 字符），重开 App 不自动连接；建立新的交互会话会替换该终端屏幕缓存，已同步的聊天气泡会保留并提供给后续会话。交互终端与讨论任务共同受“最大并发数”限制。

## 运行中修改设置

对话运行时也可以保存名称、参与角色、默认回复角色、发言顺序、讨论模式以及主持人设置；模型和推理设置同样可以保存。当前提交的任务使用启动时的角色配置、项目目录和讨论规则，保存的新设置用于下一次任务。已建立的交互终端保持原连接配置，修改模型等启动参数后需重新建立连接。

删除正在运行的对话／项目、重建原生 session、切换共用账号的登录、更新正在使用的 CLI 仍需要先结束相关任务，因为这些操作会改变或移除当前使用的进程及数据。

## 任务栏完成提醒

任务栏红点／数字和闪烁以整次提交的任务结束为准。群聊会等待所有发言、CLI 收尾以及需要的主持人判断；角色内部调用生图技能完成时，只更新图片消息，不提前触发任务栏提醒。单独发送 `/image` 的任务仍会在完成或失败后提醒。

新任务执行期间，该对话之前的未读状态保留，但暂不计入任务栏数字；任务结束后恢复提醒。其他对话已完成的未读回复仍正常计数。打开对应对话并滚到最底部后清除未读状态。延长 CLI 收尾等待不会把任务栏提醒提前。
